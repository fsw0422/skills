# Building a writing profile

Build the user's profile from their own Slack messages, then save it to the profile directory (`$WRITE_AS_ME_DIR` or `~/.config/write-as-me/`) using `profile-template.md`.

Run the collection and analysis in a subagent when one is available, so raw messages stay out of the main conversation. The subagent returns only the analysis.

## Rules

- Read-only in Slack: no messages, drafts, reactions, or canvases.
- The profile is private. Never write it into a repository or anywhere public.
- Paraphrase examples. Replace people's names, customer and company names, ticket details, and internal URLs with placeholders (`<PR link>`, `<team>`, `<ticket>`).
- Leave out profanity, even if the user uses it. Note only that it was excluded.
- Don't infer or record sensitive personal attributes (health, nationality, native language, religion, and so on). Describe mechanics ("drops articles in casual messages"), not reasons.
- No secrets, tokens, or credentials.

## Collect

1. Get the user's Slack ID from their profile (the connector's user-profile tool with no user ID returns the current user).
2. Search their messages (`from:<@USER_ID>`) and paginate. Aim for 200-300 messages, weighted to the last ~6 months with some older ones. Vary date windows, channel types (channels, threads, DMs) and topics, so one conversation doesn't dominate.
3. Read 10-15 full threads where they replied, to see replies in context: answering questions, incident or on-call replies, review requests, talking to their manager, casual chat, other teams.
4. Skip pasted AI output (em dashes, headers, tables, "Generated by ..."), logs, code, and bot content when judging style. Do note how they format code and links.

## Analyze

Give rough frequencies where possible (e.g. "~70% of statements have no final period").

1. Length and structure: one-liners vs paragraphs, bursts of short messages, bullets, line breaks.
2. Mechanics: capitalization, end punctuation, "?" and "!", abbreviations, recurring typos.
3. Tone: directness, hedging, politeness, humor.
4. Openers, tagging, thanks, sign-offs.
5. Emoji: which, how often, where.
6. Languages used, and with whom.
7. Recurring phrases.
8. How they explain technical findings: structure, detail, links, "we" vs "I", confidence, next steps.
9. How they ask for things, agree, and disagree.
10. What they never do (AI-sounding patterns to avoid).
11. Register shifts: casual internal vs cross-team vs external / formal, with concrete mechanical differences.
12. A "slightly formal" baseline: which habits to keep and which to tidy.

## Save and confirm

1. Fill `style-guide.md` and `examples.md` from `profile-template.md`, with 10-15 examples covering different situations and registers.
2. Show the user a short summary (key rules, register table, 2-3 examples) and apply their corrections before relying on the profile.
3. Record the sample size and date range at the top of `style-guide.md`.
4. Offer to keep the profile in a private Git repository cloned at the profile directory, so it syncs across machines. Only ever create it as private.
